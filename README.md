## О проекте

**«Рецепты»** — открытая кулинарная веб-библиотека с поиском блюд, справочными сведениями о приготовлении, подбором по принципам питания и мастером недельного меню. Сайт работает как статический веб-проект на GitHub Pages: для просмотра рецептов не требуется регистрация.

Каталог объединяет **50 карточек**. Для **44 рецептов** создана структурированная база ингредиентов с расчётными показателями пищевой ценности; **6 справочных карточек** пока не имеют полной структурированной рецептуры и не показывают выдуманные значения КБЖУ.

## Поиск и классификация

На главной странице доступны фильтры по **названию и ингредиентам**, **разделу**, **приёму пищи**, **калорийности** и **принципам питания**.

В каталоге представлены категории: веганское, вегетарианское, мясное и рыбное питание; диетическое, диабетическое, безглютеновое, бессолевое и низкоуглеводное. Для принципов питания предусмотрены пояснения при наведении курсора или выборе категории.

**Калорийность на 100 г:** низкая — менее 100 ккал, средняя — 100–200 ккал, высокая — более 200 ккал. Классификация ориентировочная.

> Диетические метки — кулинарная классификация, а не подтверждение медицинской пригодности блюда. При диабете важно учитывать углеводы и назначенную терапию; при целиакии — состав и риск перекрёстного загрязнения; при ограничении натрия — содержание соли в исходных продуктах.

## Мастер «Меню на неделю»

[**Открыть мастер недельного меню**](https://wadi-li.github.io/recipes/menu/)

Мастер помогает составить рацион на семь дней из доступных рецептов.

1. **Выберите принципы питания.** Допускается несколько ограничений одновременно. Если для выбранного сочетания не хватает блюд, мастер сообщает об этом вместо подстановки неподходящих рецептов.
2. **Настройте меню:** количество человек (1–20), два или три приёма пищи в день, исключаемые продукты через запятую, дату начала недели.
3. **Создайте меню на семь дней.** В каждом дне можно выбрать другое блюдо из подходящих вариантов и открыть его рецепт.
4. **Получите список покупок.** Одинаковые ингредиенты суммируются по всем выбранным блюдам с учётом числа человек.
5. **Сохраните или экспортируйте результат.** Доступны сохранение меню в браузере, копирование, печать/PDF и скачивание списка покупок в CSV.

Поля настроек имеют адаптивную ширину: на широком экране размещаются в одной строке, на небольших экранах перестраиваются в две или одну колонку.

### Как рассчитываются покупки

Для каждого рецепта используются **структурированные ингредиенты**: идентификатор продукта, количество и единица измерения. Мастер суммирует количества одинаковых продуктов, а не пытается извлечь их из произвольного текста рецепта. Вода не включается в закупочный список.

Исходная порционность в текущей базе: **4 порции для супов**, **2 порции для остальных структурированных блюд**. Количества пропорционально пересчитываются на число человек. Для блюд без полной рецептуры точный список покупок не формируется.

## КБЖУ и клетчатка

Для структурированных рецептов выводятся:

- **К** — калорийность, ккал;
- **Б** — белки, г;
- **Ж** — жиры, г;
- **У** — углеводы, г;
- **Клетчатка**, г.

Значения рассчитываются **на порцию и на 100 г** по одной базе продуктов. В ней предусмотрены усреднённые показатели на 100 г ингредиента и количество каждого ингредиента в рецепте. Это позволяет использовать общие исходные данные для карточек рецептов и недельного планировщика.

**Важно:** значения приблизительные. Текущий расчёт не моделирует изменение массы при приготовлении, испарение воды, технологические потери, конкретные торговые марки и необязательные добавки. Указанная масса порции — расчётная, а не измеренная масса готового блюда. Для медицинских диет необходимо отдельно учитывать индивидуальные требования.

### Единая модель данных

Файл `assets/recipes-data.js` содержит:

- `window.RECIPES_INGREDIENTS` — справочник продуктов с названиями, единицами и нутриентами;
- `window.RECIPES_DATA` — карточки рецептов, состав, инструкции, категории и исходную порционность;
- `ingredientsStructured` — массив ингредиентов рецепта с `ingredientId`, `amount` и `unit`;
- `yieldServings` — количество исходных порций;
- `nutrition` — расчётные значения на порцию и 100 г.

При изменении состава или количества ингредиентов **показатели КБЖУ пересчитываются из общей модели**. Список покупок использует те же `ingredientsStructured` и `yieldServings`. Для шести неполных карточек `ingredientsStructured = null` и `nutrition = null`.

## Как запустить локально

Проект не требует сборщика, сервера приложений или установки пакетов.

1. Скачайте репозиторий через **Code → Download ZIP** либо выполните:
   ```bash
   git clone https://github.com/wadi-li/recipes.git
   ```
2. Откройте `index.html` в браузере.
3. Для проверки поведения как на GitHub Pages можно запустить простой локальный HTTP-сервер из каталога проекта:
   ```bash
   python -m http.server 8000
   ```
   Затем откройте `http://localhost:8000/`.

Сохранение меню использует локальное хранилище браузера (**localStorage**): данные остаются на конкретном устройстве и не синхронизируются между браузерами.

## Публикация на GitHub Pages

Для репозитория `wadi-li/recipes` адрес публикации:

**https://wadi-li.github.io/recipes/**

Настройка: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**. После изменения файлов в ветке публикации GitHub Pages обновляет сайт; обновление может происходить с задержкой.
